# Birthday Games

Мини-сервис учёта баллов для игр на дне рождения. Гости смотрят рейтинг и
правила игр, администратор вносит результаты через скрытую страницу `/adminka`
(без авторизации — see "Adminka" ниже).

## Стек

- Next.js 14 (App Router) + TypeScript
- Prisma + SQLite
- Tailwind CSS

## Быстрый старт

```bash
npm install
cp .env.example .env
npm run db:push   # создать таблицы
npm run db:seed   # засеять 14 игроков и примеры игр
npm run dev
```

Сайт: `http://localhost:3000`
Админка: `http://localhost:3000/adminka`

## Запуск на вечеринке (локальная Wi-Fi сеть)

```bash
npm run build
npm run start -- -H 0.0.0.0 -p 3000
```

Затем зайти с любого телефона в той же Wi-Fi сети по адресу
`http://<локальный-IP-компьютера>:3000`.

## Деплой на shared-хостинг с ISPmanager (Node.js-приложение)

На хостингах с ISPmanager Node.js-приложения обычно работают через Phusion
Passenger: панель сама поднимает процесс и пробрасывает домен на него, но для
этого нужен фиксированный JS-файл запуска — им не подходит `next start`
напрямую. Для этого в проекте есть `server.js` (команда `npm run
start:passenger`), который оборачивает Next.js в обычный http-сервер и слушает
порт из `process.env.PORT`, как того ждёт Passenger.

1. **В ISPmanager**: откройте домен → раздел «Node.js» → создайте приложение:
   - версия Node.js — 18.x или 20.x (ниже 18 не хватит для Next.js 14 / Prisma 5);
   - корневая директория — куда будете заливать код;
   - файл запуска (startup file) — `server.js`;
   - режим — production.

   После создания панель обычно показывает команду активации Node-окружения
   для SSH (что-то вроде `source .../nodevenv/.../bin/activate`) — она нужна
   на следующем шаге. Точные названия полей могут отличаться у вашего
   провайдера — ориентируйтесь на «файл запуска» / «entry point».

2. **По SSH**, из корневой директории приложения:

   ```bash
   # активировать Node-окружение командой из панели (см. шаг 1)
   git clone <URL-репозитория> .        # или загрузите код файловым менеджером
   npm install
   cp .env.example .env
   ```

   В `.env` укажите путь к SQLite-файлу вне директории, которую перезаписывает
   деплой (иначе база будет теряться при каждом обновлении кода), например:

   ```
   DATABASE_URL="file:/var/www/<user>/data/birthday-games.db"
   ```

   Дальше:

   ```bash
   npx prisma db push   # создать таблицы по этому DATABASE_URL
   npm run db:seed      # засеять 14 игроков и примеры игр
   npm run build         # next build (нужен перед запуском в production)
   ```

3. В панели ISPmanager нажмите «Перезапустить» приложение, чтобы Passenger
   подхватил свежую сборку. Домен уже привязан — значит сайт сразу откроется
   на вашем адресе, SSL можно включить там же через Let's Encrypt.

4. После каждого обновления кода на сервере: `git pull`, `npm install` (если
   менялись зависимости), `npm run build`, затем «Перезапустить» в панели.

⚠️ SQLite нормально работает на обычном сервере с постоянным диском (в
отличие от serverless-платформ вроде Vercel, где база обнулялась бы между
вызовами) — на этом хостинге дополнительных телодвижений не нужно, важно
только держать файл БД вне пересобираемой директории (см. шаг 2).

⚠️ **Важно про `/adminka`**: пока сайт был доступен только в локальной Wi-Fi
сети на вечеринке, защита «через неизвестность» была разумным компромиссом.
На реальном домене `/adminka` теоретически может найти кто угодно в интернете
(перебором, через логи, через случайную ссылку и т.д.). Если админка будет
жить дольше одного вечера — стоит закрыть её хотя бы паролем на уровне
хостинга (в ISPmanager это обычно раздел «Защищённые директории» на домене)
или добавить Basic Auth прямо в приложение. Могу добавить второе по запросу.

## Adminka

`/adminka` — без пароля и без ссылок из публичного интерфейса (защита "через
неизвестность", осознанный компромисс для скорости, см. ТЗ). Страница закрыта
от индексации через `robots.txt` (`Disallow: /adminka`) и мета-тег
`robots: noindex`.
